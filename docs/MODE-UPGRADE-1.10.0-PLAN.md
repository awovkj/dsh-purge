# 三模式完整优化升级方案（1.10.0）

日期：2026-11-14。起点：dsh-purge-community 1.9.0 工作副本；目标：1.10.0。宿主源码目标继续为 DSH Desktop 0.2.2-rc.1，随包 awa-ddd 上游版本继续为 2.2.0。

本方案先于本轮继续实施编写。中断前仅新增了工具清单、SRC 收录规则和模式契约初稿，尚未完成接线、生成或回归。已有工作树修改是本轮升级的起点，不回退或覆盖。

## 1. 目标与产品决策

根据仓库外评审《dsh-purge-三模式全面锐评-20261114.md》逐项核实并修复，另外检查同一路径中的实际缺陷。保留红队、SRC、渗透三个独立入口，不采用报告中“合并 SRC 与渗透”的建议：用户明确要求两者承担不同的交付任务。

| 项目 | 红队 | SRC | 渗透 |
| --- | --- | --- | --- |
| 任务 | 明确演练目标、资产、协作和成果 | 发现、核实并整理可提交 SRC 的真实漏洞 | 完整测试、影响核验、覆盖和修复交付 |
| 收录 | 与当前任务有关的发现和成果 | 安全缺陷候选及已核实漏洞 | 真实漏洞，以及独立标记的加固/配置建议 |
| 单独缺安全头、banner、配置建议 | 不自称可利用漏洞 | 不进入漏洞台账和可提交漏洞数量 | 标记 hardening/informational，与漏洞数分开 |
| 取证 | 依任务书和实际前提 | 最小必要直接证据，确认后停止该漏洞的主动请求 | 依授权继续控制、影响和覆盖核验 |
| 凭据 | 本地句柄及实际身份核验 | 不增加凭据获取/读取能力 | 允许保存和使用本范围的测试凭据句柄，实际主体仍须核验 |
| 调度 | 同靶标共享名额，执行子会话为叶子 | 当前会话阶段稿 | 当前会话阶段稿 |
| 报告 | 成果、证明、覆盖和剩余 | SRC 提交所需的目标、证据、复现、影响边界、修复与待核实项 | 完整渗透报告、加固建议、复现附件、恢复和未完成覆盖 |

低危不等于“水洞”：低危但存在实际安全影响的漏洞仍可保留。高危标签也不等于可提交：改标题、填影响、自设严重级不能把缺安全头等建议变成漏洞。未知机制保留影响待核实，不用关键词列表宣称不存在。具体 SRC 项目是否接收，最终依该项目的实际规则。

## 2. 已核实事实与评审修正

1. 今天已有注册回执显示：红队 `registered-broken`，错误为 `tool-subagent-list-agents (@deepseek-ai/dsh-tool-subagent-control/list-agents): never started`；SRC、渗透为 `registered`。无限制模式也受到同一旧入口影响。此证据确认失败行，不能证明新的源码已在 GUI 恢复。
2. `adaptListAgents` 仅使用 Node `createRequire`，只识别 `ERR_PACKAGE_PATH_NOT_EXPORTED` 和固定版本；而当前 profile 的依赖可能由宿主 Loader 路由，普通 Node 解析不能代替它。应根据本实例实际主模块是否已提供 `list_agents` 做确定性兼容，而不是盲删失效行。
3. 红队注册在拿到 registry 后只尝试一次；失败或 broken 后没有受控恢复。SRC/渗透有重试，但注册、状态和回收实现重复，应统一关键生命周期。
4. 评审称 SRC 完全没有执行停测检查，与当前工作副本不符：`awa-integration.js` 已有 `assertSourceStops`，随包 `assessment_mode.py` 也有 native 停测。需要修复实际漏口：间接配方、模板目标、规范化、部分执行路径与原生/来源停止的一致性。
5. 红队通用 shell 不能可靠 enforce scope；只提取命令中的 URL/IP 无法覆盖变量、脚本、子进程、管道和网络库，不能以简单正则宣称完整执行边界。
6. 模式工具许可有前缀放行和红队全放行；来源报告存在模式不匹配被当成空数据的路径；SRC 收录与渗透加固项目前没有清晰的代码分类。
7. 现有多处提示词副本、英文渗透人设、重复样板和数英文代词的 anchor gate，存在真实维护与行为偏差。

## 3. P0：红队模式显示与注册生命周期

涉及 `lib/preset-compat.js`、`lib/presets-plugin.js`、`lib/redteam/index.js`、`lib/redteam/preset-composition.js`。

- 从当前 `profileContext.installAnchor` 和实际宿主 Loader 解析对应主模块；保留原始 import/resolve cause。
- 只有确认当前 control 主插件已经注册 `list_agents`，且旧行与相邻主行没有自定义配置冲突时，才在内存中删除冗余子路径行。未知实现继续报原生故障；不扫描其他 profile，不换另一份宿主。
- 同一注册实例使用执行锁、单个受控定时器、独立失败计数及明确终态。服务晚到可重试；卸载取消待处理重试，迟到注册释放；旧实例不能写新实例的回执。
- 所有注册统一检查真实 registry 的 broken 状态；返回 disposer 不等于健康。失败回收已创建父/子声明，并保留失败行、阶段和错误码。
- 兼容转换只改注册时的对象，保留用户 YAML、显示名称、人设、其他插件行和明确子任务限制。自动迁移只支持可逐项证明等价的策略。

验收：主模块已包含 list_agents 时旧子路径不再导致 broken；主模块不包含时不能移除；用户特殊配置保持；晚到、失败后恢复、重复注册、卸载中完成和注销错误都有行为测试。可用实际宿主时再在独立 home 创建空白 Agent 核对工具目录，不调用模型。

## 4. P0：范围与实际执行入口

涉及 `assessment-policy.js`、`mode-tools.js`、`session-policy.js`、`store-core.js`、`tools.js` 和实际评估入口。

- 工具、存储操作、展示工具集中定义显式清单；未知名字按模式拒绝，不再根据 `redteam_` 前缀决定是否检查。
- 红队声明了 scope/exclude 时，资产、HTTP 材料、漏洞、凭据等带目标的路径使用同一范围断言；排除项优先。空范围的历史红队保持兼容，但不宣称具有目标执行围栏。
- 具有范围约束的红队会话采用 typed 评估执行入口。通用 shell、任意代码、文件写入、可继续任意后台命令、外部工作流和未审阅工具在派发前拒绝；明确本地只读与展示工具仍可用。不能用“命令里看不见目标”当作允许理由。
- 绑定和父子继承覆盖有范围的红队，不能换 preset、冷父会话或另一个 engagement 绕过原范围。角色稿、子任务和真实调度继续共用 lease。
- 会话信息显示选择的 preset、实际固定 assessment mode 及是否不匹配，解释为什么换下拉不改变既有任务。
- 异常收紧只作用于可归属的当前会话。另一个 store 或无关会话的故障不能把全部普通会话判成 SRC。

验收：范围外资产和凭据写入被拒，通用命令执行体未运行；同范围 typed 操作可进入其原有控制；父绑定在换 preset/冷启动后保留；普通会话不被无关故障影响。

## 5. P0：SRC 停止的执行一致性

涉及 `awa-integration.js`、停测目标匹配 helper、`schema.js`、随包原生 `assessment_mode.py` 及相关调用点。

- 对所有实际目标动作区分直接 URL、operation、配方控制、身份验证端点、浏览器入口与场景步骤；间接绑定离线解析，无法解析时给明确受阻回执。
- URL 规范化去掉 query/fragment 比较已停止资源，支持已登记路由模板；保留 origin、端口、方法和具体目标边界。换发现 id 或仅变 query 不能重打同一停止目标。
- 检查来源停止与原生停止，不能依赖可编辑的漏洞状态、标题或现有 evidence_refs；fixed、删除引用、另建候选都不撤销原停止。
- 拦截在实际发送前完成，错误带 `requests_sent:0`、停止标识及离线下一步。证据读取、导入、复核、报告继续可用；不同未停止目标按实际前提处理。
- 只有漏洞级直接安全证明产生停止；纯 baseline/加固建议不占用 SRC 漏洞停止语义。修改随包文件时更新并核对本地来源摘要，保留上游来源和 MIT。

验收：直接捕获、operation、配方、身份、浏览器以及模板/编码/query 别名均有发送次数断言；停止后任何受阻回执为零次发送；换状态、id、preset 不恢复；其他明确资源和离线动作可继续。

## 6. P1：SRC 收录与渗透交付分开

涉及 `src-submission.js`、模式契约、漏洞字段/存储、来源 exchange、复核、SRC/渗透/合并报告和双端 UI。

- 漏洞台账增加可兼容的结构化类型/类别与提交状态，模型输入属于候选分析；确认与 observed 仍由可信回执和完整 machine proof 决定。
- SRC 新增和更新入口先检查配置/信息项，给出 `SRC_NOT_SUBMITTABLE` 及不可自动重试的处理说明，不写入漏洞表。
- 已有历史信息项不删除原材料；SRC 查询、导入与提交报告从漏洞分母中明确排除，单列历史排除数量。待核实真实漏洞保留候选分母，不按严重级过滤。
- 当前可信 proof 的 category、scope 和具体 claim 决定确认内容，不允许自填类别、影响或标题绕过收录或放大影响。
- SRC 报告交付真实目标、证据引用、最低必要复现、实际观察、影响限制、修复建议和未核实/受阻项；只有当前有效直接证明才显示可提交状态。
- 根据用户补充的“参照漏洞提交流程”，提供固定 submission 指引：读实际平台规则与范围、提出具体安全假设、最小直接验证、查重、整理前提/复现/预期与实际/影响/修复/证据、操作者提交与平台复核。代码分别显示漏洞证明状态与提交草稿完整性；缺规则或材料保留缺项，不猜平台接收或奖励，不自动提交。
- 渗透报告保留配置建议，单独标记 hardening/informational，与已核实安全漏洞计数分开；测试覆盖及授权变更/恢复继续使用原引擎契约。
- 渗透保存本范围测试凭据通过现有加密 vault/句柄流程；SRC 凭据禁用规则保留。浏览器或某身份缺失只阻塞依赖项。

验收：缺头、banner 和配置建议在 SRC 不新增漏洞，伪造 high/category/impact 不能绕过；实际低危安全缺陷保留；已有信息项不进入提交报告和导入；渗透可保留建议且计数分离；模型不能自授 observed。

## 7. P1：策略单一来源、样板和 anchor gate

- 模式策略正文以代码中的模式契约为单一来源，生成包内 SRC/渗透人设、随包技能政策段及固定文档的政策段；渗透统一中文。角色稿仅返回该阶段的增量职责，运行时根据实际固定模式提供同一策略。
- 注册时对旧人设不覆盖正文，通过本模式 section 补充当前固定规则，保留用户自定义 persona；模板生成与用户迁移区分处理。
- todo/present/compaction 默认值放入共享生成/兼容 helper，仅补缺失字段，不覆盖用户明确值。新增生成检查，防止版本和样板漂移让整个预设消失。
- anchor 不再数英文代词。输出 bootstrap 只依据实际工具/步骤/回合事件，明确 maxBootstrapSteps 生效条件，不能被 promoteAfterFirstResponse 提前短路。
- 工作区说明不应被重写成“与任务无关”：保留实际规则，仅对已明确允许的提示展示调整做独立处理；压缩后的事件游标避免重复计步。
- 模式菜单顺序为 SRC、渗透、红队，辅助子预设随父显示；顺序改变不更改当前任务或默认选择。

验收：生成物与源契约一致；当前模式只渲染对应规则，角色稿不重复完整规则；todo 明确值保留；中文/英文推理不影响 bootstrap；两步配置不能一工具步提前放开；已有宿主 maxTokens 不被误删；工作区规则保留。

## 8. P2：分页与报告 API

- 导入、复核、交付采用本地服务签发的 `page_token` 和可直接调用的 `next` 对象。签名绑定靶标、模式、流类型、页大小和复核语义，不能跨流、跨靶标或篡改 offset。
- 交付页 token 内持有各明细游标，模型只复用 next 参数。服务端保持页大小预算；并发切换靶标和卸载用现有 UI generation 保护。
- 旧 offset API 保留兼容；同时传 token 和旧 offset/冲突参数明确拒绝。新提示词不需要教模型手动管理四个整数。
- SRC/渗透报告在非同模式靶标上返回明确模式不匹配错误，不能把失败解释为零发现的成功报告。
- 保留 SRC 发现报告、渗透完整报告和合并首页三个有明确用途的产物，不强行删除用户已有报告和附件。生成报告不初始化评估、不请求目标、不自动结项。

验收：连续翻页无重复/遗漏，token 错流/错靶标/篡改/冲突被拒，复核 verify 语义不能被 token 改换；旧调用兼容；模式不匹配为明确失败，零漏洞只在正确模式里代表实际零项。

## 9. 未提及问题的发现与修复

按真实调用链检查：注册与 Loader、绑定与守卫、漏洞写入/过滤/复核、分页、报告、双端 UI 和随包原生策略。对发现的每一项记录“触发条件—后果—修复—验证”。

优先检查已见风险：只认包导出错误导致兼容遗漏；注册成功但 broken 的回收与重试；角色规则重复注入；漏洞更新参数被验证却未实际保存目标/类别；未知字段绕过本模式守卫；历史信息项污染 SRC 导入/分母；签发游标是否真正绑定操作；bootstrap 覆盖宿主 token 上限及丢失工作区指令。修复以可复现行为为依据，不把评审推断或“没有测试”自动写成已确认 bug。
