# 1.9.0 源码优化升级

日期：2026-11-14。根据 1.8.1 项目评审完成本地源码优化，覆盖红队、SRC、渗透模式及其共用证据、评估、调度、凭据、面板和部署模块。内置评估上游继续为 **awa-ddd 2.2.0**；1.9.0 是 dsh-purge 的本地适配版本。

**本轮按用户要求未运行测试、验证、自检、运行时探测或目标请求。** 仅编辑源码、生成来源清单和面板文件。没有安装依赖、打包发布、安装插件、应用宿主补丁或重启 DSH。此前的隔离评审与回归记录属于改动前证据，不能作为本版本验收结果。

主要变化：

- 模型在三种模式中统一只能登记 `claimed/inferred`；`observed` 来自可信代码采集回执。自由 `verified_result` 不再授予观察状态，历史 observed 保留并标注 `legacy_unattested`。
- 来源确认与报告共用发现证明契约，绑定靶标、发现、目标、operation、input、类别、原生判据与发现、完整哈希、证明范围及级别上限。同 URL 的其他命题不能继承确认。
- v1/v2 机器发现的标题、类别、影响和证明范围由判据生成。人工表述保留为声明；review/bind 使用实际机器发现，历史缺少新契约的机器标签进入待复核。
- 高价值积分的可信证据要求改为新默认开启，保留操作者明确保存的关闭偏好。通用工具回执不能独立证明漏洞或主机、系统、域名控制。
- v2 请求构造保留实际基线的非测试字段，统一 query 编码、嵌套 JSON Pointer 和真实路径绑定；过滤认证与传输头。实际执行、离线 verify 和原生复核共用完整请求/身份核验，包含执行器自动生成的头。
- SQL 三控制观察统一适配到有界判据；表达式测试要求明确的非计算器消费点及有效正常/阴性对照；严重度受证明上限约束。写预算与冻结写控制数量保持一致，仍需身份、资源、fixture 与变更许可。
- 自动 provider 能力与可补齐前提分开。未实现族保留受阻；相关真实前提变化后重新准备，保留失败历史和冷却。失败保存 run 和恢复入口，未知写入保留待读回/协调状态。
- 同靶标所有绑定根会话共享 SQLite 委派 lease；实际派发自动占位，运行 ID 与会话 ID 显式关联，已知子任务恢复复用名额，执行子会话为叶子。未知派发状态保留占位。
- 新凭据使用本地 AES-256-GCM 保存，默认通过 `cred_<id>` 句柄查询和使用。界面仅在明确点击时读取单条实际值；句柄会话在首次身份验证前固定 origin，后续仍须核实服务端主体与角色。
- 将角色文本、发现证明、可信采集、凭据、调度、运行前提和工作流提示拆为独立模块。双端面板展示当前证明、待复核标签、凭据状态及分层运行前提。
- 部署改为固定版本锁与摘要下载助手；不再追 latest、自动删除疑似坏文件、安装浮动依赖或改系统源/代理。缺版本或摘要明确受阻，部署回执与运行能力分开。
- 随包来源清单记录本地适配及新增自有模块。显式同步仅对已记录的上游哈希保留适配，漂移要求重新审阅，`--force` 不自动授权覆盖契约。

兼容变化、模式能力、恢复前提和交付限制见 [完整升级说明](../MODE-UPGRADE-1.9.0.md)。工具锁与操作者覆盖见 [固定工具部署](../TOOLKIT-PINS.md)。历史数据与用户提示词、规则、设置和 YAML 原文不会由本次源码编辑迁移或覆盖。
