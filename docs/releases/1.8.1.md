# 1.8.1 红队、SRC 修复与内置渗透模式

日期：2026-11-12。基于 dsh-purge 1.8.0、独立 awa-ddd 2.2.0 与本机《红队与SRC模式融入适配完整分析》实施。当前交付为本地源码与面板文件，随包评估引擎继续使用 2.2.0。

后续按用户提供的 `session.v4.jsonl` 继续修复 SRC 使用问题，并增加独立渗透模式，直接调用随包 awa-ddd 核心测试与生成报告。没有重新同步或运行外部 AWA 安装，既有未提交的用户改动继续保留。

继续处理三种模式一起缺失：已有回执均指向共享 `redteam-tools` 的 `never started`，无限制预设注册成功。工具 SDK 改为在异步 `apply` 中按当前 profile 加载；本包工具行固定到当前安装源码并在注册前保留原始导入异常。内置预设重试串行、各模式失败预算独立，卸载取消定时器与迟到注册。修改保存在工作区，没有替换当前安装或宣称 GUI 已恢复，详见 [模式加载修复](../preset-mode-loading.md)。

初始升级时用户明确要求不进行验证与测试，因此当时只生成本地交付文件，没有运行测试、语法/文档检查、完整性校验、dry-run、smoke、运行时探测或目标请求。随后针对另一次渗透会话实施修复，并运行本地隔离回归、语法与文档检查，实际结果见 [渗透会话诊断](../pentest-session-v4-analysis.md)。没有安装依赖、迁移用户原数据库、打 TGZ、发布、安装到当前 DSH、应用宿主补丁或重启，也没有回放原靶标或运行真实浏览器。面板构建与隔离回归不能据此证明完整桌面界面、宿主补丁及升级迁移已验收；1.8.0 历史测试记录同样不能替代本版验收。

## session.v4 修复与渗透模式

已有会话包含540个事件、80个step、133次工具调用；21次失败调用，另有一个 assessment 批次失败子项。末尾仍有 review 35、blocked 1、unresolved 36，frontier 为0，没有 finalization，另有28个操作缺少安全测试义务。正常 baseline 与零候选不能证明安全，原会话属于未完成阶段稿。完整计数、分类与边界见 [脱敏诊断](../src-session-v4-analysis.md)，原会话和目标材料不进入仓库。

新增门面 `evidence.read`，离线读取本靶标当前工件的真实 JSON 结构或脱敏文本，避免反复猜 selector；截断与旧 lineage 保留，不授予确认。新增 `surface.from_evidence`，使用随包 AST 实现解析完整JS或严格连续206分片，最多32个/2 MiB，需要同URL、operation、身份、强ETag与identity编码。缺片只返回提示，不自动请求。SRC 的65536字节/15秒预算、写入、scenario与主动外部适配器限制继续保留。

surface.batch 逐项预检查scope并保留原始索引，非法编码路径不再拖累合法登记项；证据跨操作、selector/JSON与不完整frontier错误提供离线恢复说明。模型指引、工具help及报告明确baseline只解释正常响应，不把HTTP 200、长度相同或请求条数当安全测试。

新增 `pentest` 预设与 `assessment_mode:pentest` 靶标，scope/exclude与会话绑定固定。内置核心使用普通assessment策略，不采用SRC直接证据停测；已有SRC任务不能换模式。模型提交只登记claimed/inferred，实际测试继续遵循身份、自有资源、fixture与变更前提，不增加通用shell、独立外部AWA或委派入口。

`redteam_pentest_report`、面板渗透报告与源码导出脚本`--pentest`调用内置`report.build profile:full stage:draft`。合并范围、资产、发现、证据、影响、修复和未完成分母，保留v1技术/复现附件或v2矩阵及配方/控制详解。v2的当前项目发现分别注明与当前Campaign关系；机器与reviewed质量分列。保存reports/pentest-report.md/.json；预览也创建版本化原生本地快照，不初始化、不请求目标或自动结项。可移动导出携带哈希匹配附件与相对链接。[使用和预算](../PENTEST.md)。

浏览器定位修正默认目录假设，复用操作者PURGE_PLAYWRIGHT_ROOT或实际DSH_HOME，支持已有playwright/playwright-core，Chromium缓存按系统布局独立定位。随包browser.py的适配写入源码模板与该文件bundled哈希/说明，原上游版本、哈希、MIT及版权保留。仅生成交付元数据，没有执行完整性检查、运行浏览器或安装缺件。

## 宿主续跑

另一次渗透模式 session.v4 中，279次工具调用仍没有 identity.verify、情景/配方测试或来源复核，三次评估全是baseline，最后保留227项未完成。本轮补上 `value.hash`、私下保留状态的 `cookie_evidence_ids`、脱敏响应头、未验证Cookie会话与真实主体/角色验证，并从完整OpenAPI/结构化Spring映射导入明确接口；JSON小页可返回脱敏标量。新增固定 `redteam_pentest_runbook` 推动认证、按输入安全控制和机器复核。报告工具返回有界文件回执，完整Markdown/JSON与原生附件保留；续跑预算只由新实际请求/响应材料、身份验证或安全实验重置，声明/consumer/N/A/baseline/checkpoint不重置，未评估义务先`assessment.prepare`。实际诊断与隔离验证见 [渗透会话诊断](../pentest-session-v4-analysis.md)，本轮没有访问原靶标。

新增 `assessment-guidance.js` 与 `assessment-continuation.js`。门面保留引擎结果并提供下一步，宿主控制器只消费真实执行回执和持久会话绑定，不信模型填写的 `source_meta`。当前回合结束时重新读取本地台账；完整性不足或停止字段矛盾时保留 unknown/unfinished。

v1 使用当前 `plan.audit`、continuation、frontier 与 finalization。v2 使用当前 `campaign.status` 的 engine delivery、remaining、dimensions，分别处理 active、paused、partial delivery 和 completed。v2 `campaign.next` 仅在本地准备配方并推进游标，提示本身不安排 `test.run`。

用户取消、新输入、回合变化、绑定变化及 SRC 停止优先。每个相同进展最多三次提醒，审计和分页有时间/数量预算，无新材料或只受阻时保留未完成 checkpoint。失败材料身份忽略分页、行政处置和无关任务进展；引用、具体身份、输入签名或实际前提变化后才形成新材料。未知影响的中断先离线 inspect/recover，不自动重放。

## SRC 技能与停止台账

随包 `src-discovery` 同步到 `$DSH_HOME/redteam/src-skills/src-discovery/`，红队技能根也获得同份技能。SRC 的原生技能根只加载专用目录，`redteam_src_runbook` 直接读取当前安装的固定技能或工作流，不接受任意路径。旧 SRC 预设只在注册时补充内存组合，保留原用户文件和已有注册诊断。

新增来源库 `src_source_stop`，原目标、证据及停止时间独立保存，禁止更新/删除。正常迁移会纳入仍有明确直接证据停止标记的历史记录，后续 fixed/candidate、标题/目标编辑或删除发现不撤销原目标停止；不凭空恢复已经无法识别的旧停止。本次没有打开或迁移用户数据库。

SRC 模型仍只能登记 claimed/inferred；确认继续要求本靶标当前机器证明复核，或可信操作员/代码路径实际核实的 observed 直接证据。普通 Purge 注入、通用 shell、委派、独立外部 AWA 和深度利用入口不加入 SRC。

## 运行环境与操作者偏好

「内置评估」增加运行元数据、解释器与 native/WSL 后端表单、超时、SRC 注册回执和技能同步状态。已有上下文的后端与 WSL 发行版固定；配置冲突只报告并拒绝执行，不迁移或重建台账。损坏/不可读的现有设置在写入时停止，避免以空对象覆盖用户配置。

`assessmentRuntimeProbe` 与 `redteam_preflight` 可显式探测本地 Python；有现有上下文时可启动并关闭空白 Chromium，零目标请求、不初始化评估。HTTP 与浏览器就绪分别返回，浏览器探测回执只属于实际探测的靶标。持久注册回执和文件定位不等于当前 GUI/解释器/浏览器实际可用。本次没有调用这些入口。

`continuationGuard` 默认开启，保存为 `assessmentContinuationGuard`。`requireAssessmentForHighValueScore` 默认关闭，操作者开启后约束后续 server-host/central-system/domain-control 得分写入。两项保存到本插件 settings，不修改模型提示词、profile 权限、代理或其他插件偏好。

## 得分证据与交付报告

记分支持最多 32 个同靶标 ev_id，核对完整语义哈希、同具体目标/服务和 observed 核实关联。高价值还需实际 `observation`、对应 `score_outcome.code` 与足够基础分值档位，不包含倍率；漏洞 finding 不自动证明主机或域名控制。历史文字保留，报告标注 legacy_text/pending/observed。共享封顶输入已折算倍率时不再次应用倍率，计算更正不重写旧得分记录。

新增 `redteam_delivery_report` 与 `assessmentReport`，直接读取当前已有覆盖，合并全量得分汇总、来源发现分母、v1/v2 剩余项和 SRC 停止。未初始化、不可读或绑定变化的覆盖保持 unknown/unfinished，不自动 start/finalize 或接受 partial delivery。SRC 不宣称全部范围耗尽，其他模式完成也只指已登记评估任务。

明细默认 50、上限 100，得分使用 `offset`，发现/停止使用 `finding_offset`，两者与候选导入及复核游标分开。首页保存 `reports/assessment-delivery.md/.json`，后续页带两类偏移后缀。公开报告省略原始请求、URL 查询值和凭据；每项引用只保留最多 32 个合法 ev_id，并统计非账本文字/超限引用的省略数量，原始记录保留。损坏引用结构停止生成，不能复制任意私有对象到公共 JSON。
