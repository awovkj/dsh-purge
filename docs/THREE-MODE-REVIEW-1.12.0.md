# 三模式1.12.0升级后复审

日期：2026-11-16。依据当前源码、生成物和 [本轮实际验证](MODE-UPGRADE-1.12.0.md)，延续 [原始锐评](THREE-MODE-AUDIT-1.11.0.md) 与 [工具调用锐评](TOOL-ROUTING-AUDIT-1.11.0.md)。

**项目目前最突出的短板是自动验证能力窄、真实端到端基准不足。1.12.0纠正了错误证明、覆盖串用和成本失真，但还不能诚实地承诺总体高准确率、高召回或四类工具已经充分接入。**

## 已经解决的硬伤

原SQL弱计数差异、普通计算器/字面反射、模型自填actual/human review、重复控制、跨origin案例混用、跨campaign分母与证明串用已进入正确反例回归。N/A草稿缩分母问题在本轮复审中再次发现并修复。旧错误确认标签需要当前证明，旧SRC停止不会被自动撤销。

20项明确只读batch能够在一个固定worker执行，并逐项重新检查动态身份、Cookie、范围与SRC停止。幂等复用是0新发送，取消/未知不重放。当前成本不再把“尝试数/工具调用数”包装成实际发包或精准度。

AI现在有具体路由触发、可复用next/fallback参数、真实profile readiness、按模式的技能索引。复审继续修复了auto漏掉HTML/DOM消费、身份workflow遗漏活动ID、认证重放fallback丢session，以及Cookie不合法备用路径。

最后一轮还发现路由可能把已有低权限请求换成默认管理员会话、丢掉实际query，并把脱敏URL误称可执行。这些现在按唯一原请求绑定，歧义、额外业务头和公开脱敏URL明确返回准备；没有弱化脱敏规则或匿名降级。通用私有请求句柄执行入口仍缺，不能因此宣称原包自动重放完整可用。

完整回归还揭露普通v1 analyst草稿误触发SRC停止校验的兼容错误，已经从自动停测入口修正，并添加零停止与显式停止拒绝反例。间接配方旧夹具改为真实冻结成员，生产membership校验没有放宽。完整测试回执与环境前提单独记录，不隐去首轮失败。

最终主回归723通过、30跳过，后置优化22/22，UI24/24、独立面板31/31及真实WSL/TscanPlus2/2通过；均无最终失败或取消。期间另有一次无关Windows换包等待态的间歇失败，独立与完整复跑通过、代码未改，日志与风险保留。跳过项和真实GUI/模型/浏览器缺口没有算成验收成功。

这些是已经落地的纠错；固定反例通过的样本规模仍有限。

## 不留情面的剩余问题

| 优先级 | 缺陷 | 对挖洞的实际影响 |
| --- | --- | --- |
| P1 | 自动provider只覆盖少量明确上下文 | SQL方言/语法、存储/DOM XSS、SSRF、上传、路径、反序列化和业务逻辑大量任务仍blocked；整体召回不能由支持族数字代替 |
| P1 | 业务安全契约仍依赖真实核对 | consumer/test_contract/allowed_roles登记本身只是声明；控制证明的行为可能是有意开放的功能，不能把模型填的消费点、访问策略或平台规则当成独立机器验证 |
| P1 | 真实模型选择基线仍没有 | 提示词、tool.route和合成评分器都不能证明模型会在需要时调用；漏选、乱用、错误参数和token收益尚无实测 |
| P1 | 实际Playwright/Yak链未验收 | 浏览器XSS仍基于模拟观察；Yak缺默认运行件，不能据MCP模拟成功宣称可用于真实工作 |
| P1 | 宿主/GUI/调度缺完整验收 | 旧Loader只证明当时预设与空白工具目录；86条补丁、真实guard、父子绑定、lease/cap、取消与turn-stopping仍缺本版真实回执 |
| P1 | 全局宿主拆闸与靶标策略并存 | scoped模式的typed门面有守卫，空范围历史红队仍兼容通用工具；不能向操作者承诺整个宿主和其它预设都是目标隔离环境 |
| P2 | 安全判据可确认的语法范围很窄 | 五SQL控制需要真实quoted string equality与非空计数；模板只适配明确Jinja消费点；无法把局部成立扩成任意SQL/模板影响 |
| P2 | 工具接入是窄profile | Yakit GUI没有自动化，Yak仅公开GET重放；TscanPlus读表不运行整套扫描/PoC/JWT；多数Kali工具只是目录项 |
| P2 | 私有请求绑定尚无通用执行入口 | URL/query脱敏后不能直接复用；额外业务头与匿名Cookie不能丢弃凑适配，复杂浏览器/原包任务仍需准备与已有明确typed配方 |
| P2 | 实际工具验收样本浅 | TscanPlus验收只读随机空namespace；WSL只测固定worker/本地HTTP/AST及sqlmap版本，未测大结果、真实发现导入或各工具完整闭环 |
| P2 | 吞吐与成本仍有空白 | 没有连接池；匿名Cookie链仍逐项门面；response_bytes只是捕获正文；浏览器完整子请求、CPU与可信tokens尚未计量 |
| P2 | 发现图和情报关联有限 | JS图不是跨语言污点分析，indexed map不支持；CVE/GHSA去重不能证明实际运行组件、可达根因或目标受影响 |
| P2 | 高价值成果缺可信producer | 普通漏洞证明不能证明主机/域控制；没有成果collector的条目只能pending，积分不代表真实权限 |
| P2 | 跨语言契约维护成本高 | Python action、JS公开catalogue、Node门面和宿主schema仍需同步审阅；提示词同源检查不覆盖所有typed请求语义 |

没有把未知或禁用项删掉，是当前正确的产品行为；这些缺口仍限制实际效率和召回。扩大漏洞族名称或追加payload清单不能补出缺失provider。

## 四类工具的实话

| 工具 | 1.12.0可调用路径 | 本轮实际证据 | 可给出的结论 |
| --- | --- | --- | --- |
| Playwright | native browser.probe/visit及managed反射HTML XSS | 默认模块未找到，判据测试使用模拟浏览器 | 路由/判据代码已修，实际浏览器观察未验收 |
| Yakit/Yak | tool.probe→公开GET typed replay | 默认Yak及Kali PATH未找到；TLS/schema/fuzztag控制为模拟回归 | 当前不能称运行就绪；也没有完整Yakit GUI/扫描能力 |
| TscanPlus | 绑定namespace的summary/results/routes及受控request | 实际MCP广告36工具，三个只读profile通过，隔离空namespace零目标发送 | 本机只读适配链有真实证据；主动扫描、PoC及真实结果闭环未验收 |

“需要时想到”现在有工程入口，但效果仍待真实模型测试。新15场景评分器能发现口头承诺、错协议/身份/namespace/活动、漏路由及无新材料重复调用；评分器自测通过不认证真实模型。

## 准确率与效率不能虚报

本轮安全反例没有生成错误当前证明或新SRC停止；这是对固定样本的结论。SQL真值使用实际SQLite查询，但多数安全机制HTTP和浏览器观察仍模拟。真实localhost batch证明执行守卫与回执，不能顺带证明漏洞识别准确率。

原生控制证明的是固定契约下的具体行为；契约是否准确反映实际业务安全边界仍要核对来源、正常用途与程序规则。合法的模板编辑、查询语言或普通用户已被业务授权的读取不能仅凭消费点/角色登记定成漏洞。当前没有通用业务规则真实性provider，这也是剩余误报风险，不能由更严格的请求哈希替代。

没有固定部署真值、完整支持清单、模式允许分母、真实模型工具trace和可信成本，就不能给出总体95% precision、85% recall或30%提速。候选数量、scanner结果、积分、HTTP200、报告成功和测试用例数量均不能替代这些指标。

当前可核验的是实际worker数、发送/接收数、E-ID复用、停止/取消和有限反例结果；原始覆盖分母、unsupported/blocked/unknown必须继续保留。真实模型选择率、总体精度/召回、TTFV与tokens保持未测。

## 下一批优化方案与完成定义

1. **真实模型按需选择。** 用固定模型版本、上下文、预算和15场景起步，扩充合法等价参数、缺件/过期/身份/禁止反例。任务侧只给事实/工具schema/fixture回执，expected_calls等评分答案留在独立评分端；不要把可检查case JSON当成盲测输入。由独立驱动器保存所有实际工具调用及可信宿主cost；逐项统计选择召回/精度、参数/语义合法率、闭环率和额外请求。未调用、失败与禁用不删分母。
2. **真实浏览器与Yak验收。** 先实现只绑定当前完整E-ID/身份/输入并逐派发重验的私有请求句柄，解决脱敏URL无法直接复用，不能回显凭据或放宽任意头部。使用现有已配置模块/二进制和自有本地安全/漏洞服务，核独立浏览器上下文、实际消费hash、精确dialog、Cookie目的地、取消及失效；Yak分别核实际HTTP/HTTPS、TLS/no-follow和单包行为。缺件保持明确受阻，不把安装回执当运行成功。
3. **扩大高价值provider。** 先补业务安全契约的来源与实际规则核对、实际对象/多租户及更多SQL上下文，再逐项接存储/DOM消费、SSRF控制端、路径/上传和业务状态。把合法模板/查询语言和正常角色授权纳入安全反例，登记不自授业务规则真实性。每项必须有secure/vulnerable成对真值、固定typed输入、正常/攻击/阴性控制、proof cap、fixture/未知效果与恢复契约。
4. **实测后做性能工程。** 测同预算下的首次有效漏洞时间、独立控制请求成本、启动/等待及重复率；按origin和身份代际隔离连接池、证据哈希缓存与匿名链聚合。保持动态scope/停止/Cookie重验，未知请求不自动重放。
5. **把线索关联到运行事实。** 支持有界indexed map及更多语言分析，保留动态/缺模块gap；将组件情报关联当前运行组件、可达输入与配置证明，按服务/输入/机制/根因合并候选，保留全部来源和冲突。
6. **专用DSH端到端门禁。** 在独立宿主副本核四预设、真实dispatch、父子范围和cap、取消、continuation与GUI报告；加入公共typed schema一致检查及实际模型选择回归。预生产目标另有明确范围/规则/预算回执后再验收。

这批顺序延续 [原方案M0–M6](THREE-MODE-OPTIMIZATION-PLAN.md)。本轮源码与可行本地验收完成后仍不自动发布、安装、apply或重启正式DSH。
