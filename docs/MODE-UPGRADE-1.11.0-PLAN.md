# 1.11.0：借鉴 Pojun 的发现能力与工作反馈

日期：2026-11-14。接收方为当前工作区的 dsh-purge-community 1.10.0，目标为 1.11.0 源码升级。工作区已有的未提交修改继续保留；本轮不安装、发布、apply、退出或重启正式 DSH，不改用户提示词、预设 YAML、配置或独立 Pojun 工程。

## 输入与核对原则

参照本机 Pojun 0.4.70 源码，以及《Pojun优点融入dsh-purge分析-20261114》《Pojun-vs-dsh-purge-三模式深度锐评-20261114》。建议先对照实际工作区核实，再选择实现。Pojun 的机制作为设计参考；新增代码和专题指引独立编写，不搬入其 AGPL 源码或脚本。

已核对出的差异：

- 当前 continuation 已有 `materialVersion` 和真实请求/响应、身份、安全控制的去重键。普通成功调用、声明、baseline、checkpoint 和时间戳变化不能无限重置提醒。保留这项实现，增加反馈与回归。
- 当前 `build-mode-presets.mjs` 已覆盖 SRC/渗透技能的生成政策块，渗透阶段也已有独立定义。继续完善共享证据契约和专题入口，不重新复制政策。
- `page-token.js` 的无 token 分支把 `stop_offset` 取自 `finding_offset`，是本轮需要修复的真实问题。
- 响应差分、完整 sourcemap 的离线分析、批量 typed HTTP 采集和 CWE/能力技能索引仍是实际缺口。
- 正则抽取 shell 中的目标、找不到目标即放行，不能保证实际出站范围。新增能力沿当前 typed 执行和受控本地材料入口接入。

## 本轮实现

| 能力 | 接入方式 | 可审计边界 |
| --- | --- | --- |
| 响应差分 | `redteam_assessment_run action:evidence.diff` | 两条本靶标当前完整 E-ID；结构/文本差分有预算、脱敏、来源哈希；差异不授予漏洞确认 |
| sourcemap 分析 | `action:surface.from_sourcemap` | 只处理已采集的 map 或真实 inline map；外链需明确给出已采集 E-ID；不下载，不依来源名称任意落盘 |
| 批量 HTTP 采集 | `action:http.capture_batch` | 每项走既有 capture/preflight、scope、身份、Cookie、SRC stop 和取消逻辑；有界顺序执行，未知结果停止，不自动重试 |
| 有界本地材料 | `action:workspace.list/read` | 只读当前靶标固定材料目录；不提供通用文件/代码入口，不读取凭据库、原生数据库或原始 Cookie 证据 |
| 本地漏洞情报 | `action:intel.import/search/get` | 从当前靶标 incoming 的 NVD/KEV/GHSA JSON 导入有界元数据；固定缓存、来源摘要、版本范围；没有远程同步和验证授权 |
| 技能导航 | 固定安装来源的技能目录、runbook 专题和 CWE 关联 | `cwe/class/requires` 有真实代码消费者；缺失或未知能力明确显示，文件存在不代表运行可用 |
| 失败归因 | typed 调用回执与 continuation 有界摘要 | 平台模式/范围拒绝、HTTP 权限/限流响应、运行错误和不确定派发分别显示；403 不自动解释成 WAF 或已验证安全控制 |
| 后续工作建议 | `action:workflow.advice` | 读取已有发现和当前证明，返回范围内、前提明确的离线建议；SRC 停测优先，不自动派单或请求新目标 |
| 分页修复 | `resolvePage` 和独立回归 | 发现、停止、得分及复核流各自使用原游标，token 语义保持绑定 |
| 生成物与版本 | 模式、客户端、README、AGENTS、发行说明和测试命令 | 生成物与源码同源；源码版本与发行/宿主验收分开记录 |

## 两份分析建议的处理

| 建议 | 本轮处理 |
| --- | --- |
| 产出率收尾 | 保留已有真实材料去重，补反馈和回归；不改为工具调用计数或任意台账写入计数 |
| 攻击链续跳 | 落为当前证明驱动的离线工作建议；执行仍由既有 typed 入口核验实际前提 |
| CVE 情报库 | 先落地离线 NVD/KEV/GHSA 元数据导入与检索；远程同步不在此次源码升级中自动运行 |
| PoC 脚手架 | 优先复用原生 `assessment.prepare` / `test.prepare` 的控制配方，技能说明真实 provider 与未实现项；自由脚本生成另行设计 |
| sourcemap | 实现有界离线分析；不采用 Pojun 脚本的关闭 TLS、外链自动访问、秘密回显和自动高危定级 |
| 响应差分 | 实现真实 E-ID 差分；不把忽略字段或摘要当原生 proof |
| 批量探活 | 实现批量 typed capture，只返回有界摘要与 E-ID，不直接使用 fetch/curl |
| 技能标签与 CWE 联动 | 实现固定目录、元数据消费者、专题 runbook 和 PoC 搜索关联 |
| 拒绝话术框架 | 明确平台管控来源与零目标请求，防止误记成目标防护 |
| 失败归因 | 消费 typed 状态；不从自由文本猜目标防御或推荐绕过 |
| 派发背压 | 保留同靶标原子 lease，修复未知派发不可释放名额；不冻结只读规划或绕过并发上限 |
| 纵深收敛 | 用已有材料和当前有效证明给出整理、复核及前提建议；不以资产数量否定剩余覆盖 |
| mid-run steer / trace | 保留宿主现有接口；不伪造未验收的宿主能力，本轮不另起后台调度 |
| LLM 兜底裁判 | 暂不增加。自由文本裁判不能代替出站范围或机器证明 |
| L1–L4 阶梯 | 加入审查指导；模型自填级别和假设绕过不改变 observed、confirmed、严重级上限 |
| 任务级操作约束 | 保留现有 mode、scope/exclude、identity、fixture、mutation、stop 契约；开放式文本约束不当作执行授权 |
| 冷图折叠 | 继续复用现有分页，不在本轮增加另一套图状态 |
| 成本可见性 | 不虚构宿主未返回的 token 数据；调用回执可呈现实际状态和有界样本 |
| 态势快照 | 通过本地 workflow 建议整合已有状态，不以汇总替代覆盖分母 |
| 目标验收层 | 保留现有报告和未完成契约；本轮不把模型自述目标改为完成证明 |

不增加 C2、全局 MITM 或插件层 LLM 故障转移。SRC、渗透、红队的创建时模式、持久绑定、凭据规则和报告入口继续独立，不能通过参数把旧 SRC 靶标降级。

## 验证与交付

新增测试应验证外部可见行为：真实证据完整性/lineage/范围、差分隐私、sourcemap 路径与预算、批量逐项校验/取消/未知结果、固定本地材料边界、情报导入与版本判断、技能能力缺失、当前证明失效和独立分页。

本地回归使用临时目录、数据库和合成响应。实际随包 Python 引擎可在禁止 socket 的 fixture 内验证；不访问真实目标、不运行真实浏览器。完成源码与生成后执行适用的模式、文档、客户端、随包来源和现有回归。最终实施记录应逐项写实际结果、跳过原因和剩余宿主/GUI验收边界，不能把计划写成通过。
